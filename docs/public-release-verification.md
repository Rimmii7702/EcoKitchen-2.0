# EcoKitchen public-release verification

A standalone public-source edition prepared under **Option B**, with no project-wide license and no inherited Git history. [The exact file ledger](public-release-files.tsv) records included paths, substitutions, hashes, and all excluded Phase 6D/7A paths and Phase 7B screenshots. The new screenshots reuse some original filenames. The ledger distinguishes these captures by inclusion status and hash. The ledger's own hash and the verification report hash are omitted to avoid self-reference and changing the source index when test results are recorded.

## What this edition includes

- Flask, React/Vite, administrator/viewer roles, revocable sessions, secured inventory CRUD and history, expiry and low-stock alerts, FEFO and replenishment, and read-only what-if calculations.
- Independently authored fictional ingredient, recipe, catalog and partial weekly-sales CSVs, plus an explicitly labeled static fictional saved menu. Run `python -m tools.build_release_fixtures --check` to verify fixture bytes. Standard startup can initialize empty SQLite. `import-inventory` loads the fictional CSV, and `tools.portfolio_demo` seeds a separate relative-expiry demo with its own copy of the fictional menu. Neither uses the original data.
- The three attributed FreshRetailNet aggregate scorecards, original analysis figure, and offline reproduction code. The API reads only the aggregate holdout scorecard. The retained historical holdout covers 350,000 observations with 41.8314054769% seasonal-naive WAPE, 33.6450157277% LightGBM WAPE, and 8.1863897492 percentage points of improvement. These are normalized observed grocery sales, not restaurant demand. [Source](https://huggingface.co/datasets/Dingdong-Inc/FreshRetailNet-50K) · [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) · [Reproduction](freshretailnet-holdout.md)
- Optional Gemini recipes, fresh menus, spoilage checks, and simulated heatmaps retain their provider-backed paths and missing-credential errors. The verified synthetic-waste report and prediction code remain, but running the predictor needs a separately supplied local artifact. No paid inference is required for the demo or tests.

## Differences and withheld workflows

All 56 historical held paths and the four audit exclusions remain in the original project only. The candidate leaves out original CSVs, historical saved media and annotations, notebooks, deck and diagrams, original saved menu, generic and custom weights, internal audit artifacts, old screenshots, and original datasets and databases. The original weekly-sales audit output depends on the held CSV, so the candidate computes its partial-history screen from the new fictional fixture. The standalone legacy cost-optimizer is withheld with its inputs. The candidate architecture and README describe this narrower edition.

Image and video object detection, camera scanning, and combined annotated waste-photo analysis are unavailable. Their retained upload URLs validate input and return HTTP 503 without invoking a model. The legacy video-feed route returns 404 because this edition has no bundled playback source. The React UI offers Gemini-only spoilage checks and labels the unavailable workflows. Backend and frontend object-detection success tests and video playback tests from the original edition are not in scope. Candidate tests retain Gemini spoilage and heatmap, upload validation, real-image fixture media access and authorization, and check the withheld responses. Original tests remain in the working project.

## Licensing and publication scope

**Option A.** Restore the integration only after reviewing contributor rights, the exact Ultralytics release and terms, and the provenance of every model checkpoint and training dataset. An AGPL-3.0 distribution requires the applicable license/notices and complete corresponding source, including relevant build and installation material. Review network-use obligations if offering the software remotely and confirm the scope of the integrated work with qualified counsel. Alternatively review an Enterprise agreement that covers the intended distribution. Exporting only code and leaving out model weights does not resolve these obligations. [Ultralytics licensing](https://www.ultralytics.com/license) · [GNU AGPL-3.0](https://www.gnu.org/licenses/agpl-3.0.en.html)

**Option B, implemented here.** Withhold Ultralytics imports, model loaders, camera and annotation implementation, the integrated frontend controls, runtime and optional dependencies, and all weights. Gemini-only code and independent stock recommendations stay available. The project owner confirmed ownership of the original work, authorized publication of this reduced edition, and chose to omit a project-wide license. Keep the existing upstream notices and attribution.

[Third-party notices](third-party-notices.md) cover React, Lucide/Feather, DM Sans and Manrope, legacy CDN assets, and FreshRetailNet. Build-installed code and fonts remain under their upstream terms. A future Windows ZIP or container distribution needs the applicable full notices from the exact packages shipped, including transitive dependencies and base images. The release includes new [public screenshots](screenshots/README.md) rendered from fictional records and the aggregate scorecard. ZIP archives, generated builds, package caches, original Git metadata, credentials, private documents, and local databases are excluded.
